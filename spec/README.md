# Spec vectors

Language-neutral test vectors for the crypto kit and token formats (CONTRACTS section 8). Every implementation of GotAuth, in any language, must pass them byte for byte. Work package F3 owns this folder and documents the final format here.

## Format

- One JSON file per topic, named in kebab-case: `hotp.json`, `totp.json`, `pkce.json`, `hkdf.json`, `password-hash.json`, `sign.json`, `token-format.json`.
- Each file holds a list of cases. Every case has a `source` field that says where it comes from, for example `"RFC 6238 appendix B"` or `"generated by GotAuth, cross-checked with Node crypto.scrypt"`.
- Binary values are encoded explicitly (hex or base64url), and the encoding is named in the field name, for example `key_hex`.
- Vectors from RFCs are copied unchanged. Vectors GotAuth generates are cross-checked with an independent implementation before they are committed.

## Use in tests

```python
import pytest

from gotauth.testing import load_vectors


@pytest.mark.vectors
@pytest.mark.parametrize("case", load_vectors("pkce"))
def test_pkce(case: dict[str, str]) -> None: ...
```

`load_vectors(name)` reads `spec/<name>.json`. Run only the vector tests with `./dev.sh uv run poe vectors`.
