# Spec vectors

Language-neutral test vectors for the crypto kit and token formats (CONTRACTS section 8). Every implementation of GotAuth, in any language, must pass them byte for byte. Work package F3 owns this folder.

## Format

- One JSON file per topic, named in kebab-case. Each file is a JSON array of cases (objects).
- Every case has a `source` field that says where it comes from, for example `"RFC 6238 appendix B (SHA1 rows)"` or `"generated by GotAuth, checked with Node crypto (spec/crosscheck.mjs)"`. Many cases also have a `comment` saying what they test.
- Files that mix several kinds of case have a `kind` field.
- Binary values are encoded explicitly, and the encoding is named in the field name (`secret_hex`, `secret_b32`, `nonce_hex`). Other strings are Unicode text, used as UTF-8 bytes. The files themselves are ASCII; non-ASCII text is written with JSON `\u` escapes.
- `null` as an expected value means "rejected": `unsign` or `decrypt` returns nothing, or `pkce_s256` raises.
- Regexes (`regex` fields) must match the whole string, and are written so they mean the same in Python (`re.fullmatch`) and JavaScript.
- Vectors from RFCs are copied unchanged. Vectors GotAuth generates are recomputed by an independent implementation (`crosscheck.mjs`, below) before they are committed.

## Files

| File | Cases | Contents |
|---|---|---|
| `hotp.json` | 10 | RFC 4226 appendix D: HMAC-SHA-1 value, dynamic truncation and 6-digit code for counters 0 to 9 |
| `totp.json` | 6 | RFC 6238 appendix B, SHA1 rows: 8-digit codes. A 6-digit code is the last 6 digits |
| `pkce.json` | 10 | RFC 7636 appendix B, plus the shortest and longest allowed verifiers and verifiers the RFC 7636 section 4.1 rules reject (`challenge: null`) |
| `hkdf.json` | 9 | `kind: "rfc5869"`: RFC 5869 appendix A.1 to A.3 (HKDF-SHA256, with PRK). `kind: "derive_key"`: `derive_key(purpose, length)` for fixed secrets: HKDF-SHA256 of the UTF-8 secret, empty salt, `info = "gotauth:" + purpose` |
| `sign.json` | 25 | `kind: "sign"`: `sign(value, purpose)` with `secrets[0]`. `kind: "unsign"`: valid values, rotation (`[new, old]`), removed secrets, wrong purpose, tampered or truncated values and signatures, padded and non-canonical base64url |
| `encrypt.json` | 24 | `kind: "encrypt"`: AES-256-GCM output for a given `nonce_hex` (the kit picks random nonces). `kind: "decrypt"`: valid ciphertexts, rotation, wrong purpose, tampered ciphertext, tag and nonce, truncation, unknown versions and malformed text |
| `password-hash.json` | 35 | `kind: "scrypt"`: RFC 7914 section 12 vectors 1 to 3 (vector 4, N = 2**20, needs 1 GiB and is left out). `kind: "verify"`: `verify_password(password, stored)` with the default configuration (scrypt): GotAuth scrypt hashes, other costs (`needs_rehash`), malformed and over-limit hashes, unknown tags, bcrypt hashes as passlib made them (including passwords over 72 bytes) and argon2id hashes. Cases with `requires` need that optional extra (`bcrypt`, `argon2`) |
| `token-format.json` | 23 | `kind: "token"`: the prefixes of CONTRACTS section 7 with 43-character bodies. `token_encoding`: random bytes to token text. `hash_token`: SHA-256 hex. `otp`, `totp_secret`, `ulid`: formats with valid and invalid examples. `ulid_time`: the 10-character time part of a ULID |

`encrypt.json` is not in the CONTRACTS section 8 table yet; it pins the `encrypt` format that `account_token`, `two_factor_secret` and `jwk_private` values are stored in.

## Use in tests

```python
import pytest

from gotauth.testing import load_vectors


@pytest.mark.vectors
@pytest.mark.parametrize("case", load_vectors("pkce"))
def test_pkce(case: dict[str, str]) -> None: ...
```

`load_vectors(name)` reads `spec/<name>.json`. Run only the vector tests with `./dev.sh uv run poe vectors`. The crypto kit's own vector tests are in `tests/crypto/test_vectors.py`.

## Independent cross-check

```bash
./dev.sh node spec/crosscheck.mjs
```

`crosscheck.mjs` recomputes every case with Node's `crypto` module (HMAC, HKDF, AES-GCM, scrypt, SHA-256 and, on Node 24.7 or later, argon2id) and checks bcrypt hashes with the system `crypt(3)` through Perl. It has its own small implementation of the parsing rules, so it also shows that the vectors work outside Python. It prints any mismatch and exits with 1. `tests/crypto/test_vectors.py` runs it when `node` is installed.
